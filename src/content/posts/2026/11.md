### [Faster type-aware linting with tsrs](https://oxc.rs/blog/2026-11-17-faster-type-aware-linting-with-tsrs)

- 共有者: @sajikix

Oxlint の type-aware linting で、これまでの tsgolint に代わるバックエンドとして tsrs が使えるようになりました。tsrs は先月 Cloudflare と VoidZero が発表した TypeScript の Rust 移植で、Cloudflare、Owner.com、OpenAI のチームがすでに type-aware linting に使っているとのことです。

#### 導入方法

`tsrs` をインストールしておくと、Oxlint が自動で tsrs を使うようになります。CLI と設定はこれまでのものをそのまま使えます。

```sh
pnpm i -D oxlint tsrs
pnpx oxlint --type-aware
```

#### tsgolint との互換性

tsrs は tsgolint v7.0.2007 にある 61 ルールをすべて実装しています。設定オプション、診断、fix、suggestion も tsgolint と同じになるようにしていて、既存のプロジェクトはほとんど手を入れずに移行できるとしています。ただし現時点では互換性の改善が続いている段階で、差が見つかったら issue で報告してほしいとのことです。

#### 性能

記事では次の数値が紹介されています（いずれも「最大」の値で、計測に使ったリポジトリや条件は記事には書かれていません）。

- tsgolint 比で最大 5 倍速く、メモリ使用量は約 70% 減
- typescript-eslint 比で最大 98 倍速く、ピークメモリは最大 82% 減
- lint と型チェックを一緒に実行した場合、Oxlint + tsgolint 比で最大 7 倍速く、typescript-eslint と tsc を別々に実行する場合と比べると最大 122 倍速い

lint と型チェックを一緒に実行したときの差が大きいのは、tsrs が 1 回の TypeScript の解析で両方を処理し、同じ解析を二度行わないためです。今後は tsrs と Oxlint の統合を進め、lint と型チェックで重複している処理をさらに減らすことを検討しているそうです。

### [Building Interfaces That Understand What We Want to Do](https://agustinbarrientos.com/writing/senior-eye/interfaces-that-understand-what-we-want)

- 共有者: @nakajmg

Chrome が実験中の Decisions API を紹介する記事。内蔵モデルの Gemma 4 と EmbeddingGemma を含む複数のモデルをベンチマークで比べ、3つのデモを実装して使い勝手を検証している。

- ユーザーの入力に対して開発者が用意した選択肢から端末上のモデルが1つ選ぶ仕組み
- 文章は生成せず選択肢ごとの確率を返すだけ
- 無料。データは端末の外に出ない
- 内蔵モデルは Gemma 4 と EmbeddingGemma の2種類
  - Gemma 4 は大きめで精度が高く、そのぶん遅い。Chrome 157 ではこれだけ
  - EmbeddingGemma は小さくてかなり速いが、精度は下がる。Chrome 158 から既定で使われる
- Chrome 159 から、フラグでモデルを選べる予定
  - Gemma 4 を指定するプロパティは一時的なもので、最終版のモデルは未定
- まだフラグ付きの実験機能

考えられるユースケースとして、たとえば求人サイトの検索で「週3リモートで17時までに終わる仕事」のような自然文を入力したときに、在宅勤務可・時短勤務可などの各フィルタを選択肢として端末上のモデルが判定し、該当するものを自動で適用するなど。
外れてもユーザーがフィルタを外せるので、こういった誤判定の影響が小さい用途に向いていそう。
